# 用語集

本プロジェクトにおいて、ドメインの概念を正確に表現するため、空間や時間に関する用語を以下の通り定義し、使い分けています。

過去の設計において「セル (Cell)」という用語が複数の意味（時間の単位、木構造のノード、空間の範囲など）で乱用され混乱を招いていたため、現在のコードベースではドメイン用語としての「セル」の使用を全面的に廃止し、空間・時間・次元に関する概念を以下の通り厳格に区別・定義しています。

## 1. Interval

- **定義**: 時間軸の解像度（時間単位 `i`）を表す値。
- **コード例**: `Interval`型

## 2. TimeSpan

- **定義**: 1次元の数直線上における任意の連続した範囲 `[start, end)`。
- **特徴**: 開始値と終了値によって定義され、長さに制約はありません。木構造の境界に揃っている必要もありません。日本語では区間と呼ぶ。
- **使用例**: 「任意の時間区間」

## 3. TimeSegment

- **定義**: 1次元の数直線上において、2分岐（Segment木など）によって再帰的に分割されたブロックの1つ。
- **特徴**: 常に「2の冪乗」の長さを持ち、特定の境界にアライメントされている必要があります。任意の「区間 (TimeSpan)」を木構造に格納する場合、1つ以上の「TimeSegment」に分解して扱います。
- **使用例**: 「時間Segment (Temporal TimeSegment) へ分解する」
- **コード例**: `TimeSegments`型

## 4. FlexId
- **定義**: 複数の次元（F, X, Y, 時間など）において、それぞれが「TimeSegment」として分割された結果組み合わさってできる、多次元の空間的・時間的な範囲。
- **コード例**: `FlexId`

## 5. Dimension

- **定義**: 空間および時間における各自由度・方向（`F`, `X`, `Y`, `T` など）を表す概念。
- **命名規則**:
  - コードベース全体（関数名・変数名・定数名・型名・ドキュメント）において、空間・時間の次元を表す用語は **`dimension`**（複数形: **`dimensions`**）に統一します。
  - 過去に使われていた **`axis` / `axes`** は、次元を表す用途としては廃止・統一対象です。

- **コード例**: `Dimension` 列挙型、`FlexId::dimensions()`、`Node::covers_all_dimensions()` など

## 6. FlexTreeCore

- **定義**: `FlexId` と値 `V` を対応付けて保持する木構造の型。`SpatialIdSet`・`SpatialIdTable` の中身です。
- **命名規則**: 「木」「ツリー」と訳さず、**`FlexTreeCore`** と書きます。
- **コード例**: `FlexTreeCore<V, S>`

## 7. Node

- **定義**: `FlexTreeCore` を構成する要素。自分の `FlexId` を持たず、辿るときに親から渡される領域で意味を持ちます。次の種類があります。
  - **Leaf**: 値を1つ持つか、空。値を持つ `Leaf` が、値を持つ `FlexId` 1つに対応します。
  - **Branch**: 領域を1つの `Dimension` で2つに分けます。
  - **Skip**: 片側が空の `Branch` が続く経路を、1つにまとめます。
- **命名規則**: 「ノード」「葉」と訳さず、**`Node`**・**`Leaf`**・**`Branch`**・**`Skip`** と書きます。値を持つ領域そのものを指すときは **`FlexId`** と書きます。
- **コード例**: `Node::Leaf`、`Node::Branch`、`Node::Skip`

## 8. 子孫

- **定義**: ある `Node` から子を辿って到達できるすべての `Node`。自身は含みません。
- **命名規則**: 「配下」「部分木」「下位」とは書かず、**子孫** と書きます。自身も含めるときは「自身と子孫」と書きます。
- **使用例**: 「子孫の値の `Summary`」「自身と子孫が割っている次元」

## 9. Summary

- **定義**: `Branch` が子孫の値についてキャッシュする情報。`FlexTreeCore` と `SpatialIdTable` の型パラメーター `S` で選びます。
- **命名規則**: 「集計」と訳さず、**`Summary`** と書きます。
- **コード例**: `Summary` トレイト、`MinMax`、`ValueSet`、`NoSummary`

## 10. flex Z-order

- **定義**: 2 つの `FlexId` の間の狭義の半順序。位置をルート、続いてズーム 1, 2, … の各深さで F→X→Y→T の順に並べ、2 つの `FlexId` が最初に食い違う位置を見ます。そこで両方が割られていれば、下側にある方を前とします。片方だけが割られていなければ比較できません。
- **特徴**: Z 順（Morton 順）を、次元ごとに分割の深さが違う場合へ広げたものです。全順序ではなく、包含関係にある組と、互いに素でも最初に食い違う位置で片方だけが割られていない組は比較できません。推移律を満たします。
- **命名規則**: 「走査順」「カノニカル順」とは書かず、**flex Z-order** と書きます。識別子の接頭辞は `zorder_` とします。`z` はズームレベルを指すので、`z_` は使いません。
- **コード例**: `FlexId::zorder_cmp`、`FlexId::zorder_key`、`ZOrderRel`

## 11. Z-ordered sequence

- **定義**: 隣り合う `FlexId` が flex Z-order で狭義に増加する `(FlexId, V)` の列。推移律により、どの 2 要素も前の要素が小さくなります。
- **特徴**: `QueryIter` が満たす条件です。同じ形状でも列は一意に定まらず、同じ値の隣接する領域がまとめられているとは限りません。
- **命名規則**: 「カノニカル順の列」とは書かず、**Z-ordered sequence** と書きます。
- **コード例**: `QueryIter::from_ordered`

## 12. canonical sequence

- **定義**: Z-ordered sequence のうち、`FlexTreeCore` の規則でこれ以上まとめられないもの。`FlexTreeCore` から出てくる列がこれにあたります。
- **特徴**: 形状（領域から値への写像）に対して一意に定まります。まとめられるかは兄弟の部分木どうしを比べて決まるので、隣り合う 2 要素だけでは判定できません。このときの `FlexTreeCore` の構造を **canonical form** と呼びます。
- **命名規則**: 「正規形」「カノニカル形」とは書かず、列は **canonical sequence**、木の構造は **canonical form** と書きます。

## 共通の規則

型として存在する名前（`FlexId`・`FlexTreeCore`・`Node`・`Leaf`・`Branch`・`Skip`・`Summary` など）は、ドキュメントやコメントでも日本語に訳さず、型名のまま書きます。
